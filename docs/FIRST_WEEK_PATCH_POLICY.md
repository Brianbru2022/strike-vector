# First-week patch policy

During the release freeze and first week, accept only crashes, save loss/corruption, installation failures, objective blockers, unavoidable attacks, inaccessible essential controls or warnings, serious performance regressions, legal/privacy corrections and material storefront inaccuracies.

Every patch receives a new build ID and candidate manifest. Re-run affected automated suites plus save migration, Windows packaging, consumer identity and rollback checks. A change that alters balance, objectives or assets outside those categories returns to normal development rather than bypassing the freeze.
